# 中文视频去水印操作台

Go API 内嵌静态网页，无需前端构建工具。登录页公开，所有任务、上传与视频接口必须使用访问令牌，按令牌所属租户隔离。令牌仅存当前标签页的会话存储；退出会清除，页面和仓库不内置令牌。

## 当前实例访问

访问 `https://175.121.93.64:61591/`，使用本机 `/home/box/.config/dewatermark/console-token` 中的专用令牌登录。该文件权限为 600，映射租户为 `kelin`；GPU 端仅在 `/opt/dewatermark/config/runtime.env` 的 `API_TOKENS` 中配置。

HTTPS 使用 Caddy 内部签发证书，浏览器首次访问会提示证书不受信任。确认地址后继续，或通过受信任方式导入该实例的公开根证书。当前无可用自有域名及证书配置；未来绑定域名后可替换为受信任证书。配置中的 `default_sni` 用于处理以 IP 访问时不携带服务器名称的客户端，参见 [Caddy 官方配置文档](https://caddyserver.com/docs/caddyfile/options#default-sni)。

实例已有公网映射 `VAST_TCP_PORT_10100=61591`，此前端口空闲。独立的 `dewatermark-console` 服务在容器 10100 端口提供 HTTPS，转发到 `127.0.0.1:18080`。不需要修改原有管理入口或开放数据库、Redis。API 使用自己的令牌鉴权，无需向用户提供 Vast 管理令牌。

也可以从自己的电脑使用 SSH 转发（使用自己的私钥路径）：

```sh
ssh -i ~/.ssh/vastai_ed25519 -p 61586 -o IdentitiesOnly=yes -N -L 18080:127.0.0.1:18080 root@175.121.93.64
```

然后访问 `http://127.0.0.1:18080/`，仍需输入操作台令牌；传输经 SSH 加密。

## 使用与限制

选择本地 MP4/MOV，点击“上传并去水印”。不需要画框。单条大小不超过 200 MiB、时长不超过 30 秒，编码须为 H.264 8-bit 4:2:0。前端检查扩展名、大小和浏览器读取的时长；代理上传端调用 `ffprobe` 检查实际封装、编码、像素格式和时长，GPU worker 继续执行完整媒体校验。Go API 和 worker 均遵循 `S3_OBJECT_TAGGING=false`，关闭 R2 不支持的对象标签，改用对象元数据保存用途标记。

页面列出租户最近 100 条任务，每 4 秒刷新，列表查询仅访问数据库，支持取消排队或运行中的任务。耗时从任务创建算起，包含排队；结束后固定为创建至最终状态更新时间。运行失败显示后端原因。需要复核的任务不作为成功结果发布。

成功后点击“播放对比与下载”，同源鉴权读取原片和成品，再生成浏览器临时视频地址。关闭标签页或退出释放地址。视频加载到浏览器内存后播放，接近大小上限的原片会占用相应内存；下载文件名为“去水印成品.mp4”。结果过期后页面提示重新提交。

## 上传与新增接口

保留原有预签名上传接口供已有客户端使用。网页不使用返回的签名地址，而使用 API 同源代理，**不需要配置 R2 桶的浏览器跨域规则**，也不会向网页写入存储密钥。

- `GET /v1/jobs`：返回 `items`，每项含 `job` 和 `filename`，最近 100 条，按创建时间倒序，仅当前租户。
- `PUT /v1/uploads/{id}/content`：上传原始文件，携带访问令牌和预约时的媒体类型，大小必须与预约一致。临时落盘、检查实际媒体格式后传入 R2。临时文件在成功或失败后均删除。
- `GET /v1/jobs/{id}/media/source`：读取冻结的原片。
- `GET /v1/jobs/{id}/media/result`：仅成功且未过期的成品；支持分段读取。

现有 `POST /v1/uploads` 预约后，使用上述代理上传，再按原有 `POST /v1/jobs` 提交（幂等键使用上传编号）。任务详情、取消及既有接口保持兼容。API 读写超时调整为 10 分钟以支持视频传输；反向代理不记录请求头或访问日志。API 运行环境须安装 `ffprobe`；容器构建文件已补充 FFmpeg。

## 部署与维护

同步 `migrations` 目录（包含任务列表的租户时间索引），按已有迁移方式应用。编译 `go build -trimpath -o api ./cmd/api`，替换 `/opt/dewatermark/bin/api`。本次旧程序保留于 GPU 的 `/opt/dewatermark/bin/api.before-console`。

将本目录 `Caddyfile` 放到 `/opt/dewatermark/config/console.Caddyfile`，启动脚本放到 `/opt/supervisor-scripts/dewatermark-console.sh` 并赋予可执行权限，监督进程配置放到 `/etc/supervisor/conf.d/dewatermark-console.conf`。公网地址或映射端口改变时应同步修改配置。

```sh
supervisorctl restart dewatermark-api
supervisorctl reread
supervisorctl update
supervisorctl restart dewatermark-console
```

专用令牌使用密码学随机生成器产生至少 32 字符的随机值，仅更新 GPU 的运行配置及上述本机权限 600 的文件。不要在命令参数、版本库、截图、日志或聊天中粘贴令牌。令牌发生变化后重启 API。

## 验证

```sh
go test -race ./...
go vet ./...
```

部署集成测试 `worker/tests/test_console_integration.py` 仅在 `CONSOLE_INTEGRATION=1` 时运行，从环境读取 `API_TOKENS` 和数据库连接；应在服务端加载运行配置后执行，不能将凭证写入测试文件。覆盖列表租户隔离、跨租户详情/原片/成品/上传拒绝、无效文件/大小拒绝、取消幂等、原片/成品分段读取。取消测试只创建无调度记录的临时测试任务，结束后清理，不会提交 GPU 作业。

浏览器验收使用 `/workspace/dewatermark-test/user/clip-8s.mp4` 的原始副本，走登录、上传、提交、等待成功、双视频播放和成品下载。截图与验收文件保存在本机 `/workspace/user-videos/console/`。

浏览器脚本依赖 Playwright 和支持 H.264 的 Chromium/Chrome。可复跑完整验收（会新增一个真实 GPU 任务）：

```sh
python3 scripts/console_browser_check.py --self-signed --upload /workspace/user-videos/console/clip-8s.mp4
```

不传 `--upload` 时复验现有成功任务的真实播放、下载、截图、会话恢复及退出清除。`--self-signed` 仅用于当前自签名 HTTPS 的自动验收；日后使用受信任证书时无需此参数。

本次验收结果：指定 8 秒视频自动处理成功，耗时 284 秒；浏览器成功播放原片与成品并下载成品。Go 竞态测试及静态检查通过；Python 本地测试 32 项通过、10 项按环境跳过；GPU 部署集成测试 3 项通过。另验证了前端超 30 秒、超 200 MiB、未选文件拦截、无效令牌、窄屏布局，以及刷新恢复会话、退出清除令牌。最终截图为 `/workspace/user-videos/console/console-result.png`，窄屏截图为同目录 `console-mobile.png`，成品为同目录 `验收成品.mp4`。
