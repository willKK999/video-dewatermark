# 视频去水印系统 HLS 使用说明

## 提交与下载

操作台保留现有深色界面。在「HLS 播放列表」输入当前租户目录下的 R2 对象键，例如 `kelin/hls-test/20261110/input.m3u8`，或公开 HTTP/HTTPS 链接。对于当前存储配置对应的 R2 链接，系统识别对象路径并使用既有对象存储凭证读取，包括相对分片；对象仍限制在当前租户目录。可填写主播放列表的码率上限（bit/s）；留空选最高码率。有上限时选不超过上限的最高码率，没有符合项时选最低码率。媒体播放列表及相对路径 ts 均可直接提交。

接口沿用 `POST /v1/jobs`，请求头须带 Bearer 身份凭证及 `Idempotency-Key`：

```json
{
  "hls_input": "kelin/hls-test/20261110/input.m3u8",
  "options": {"max_short_edge": 720, "allow_downgrade": true, "hls_bandwidth": 0}
}
```

同一幂等键与同一请求返回原任务，内容不同返回冲突。操作台在提交结果未确认及任务运行期间保留幂等键；任务进入终态后再次提交会创建新任务。需要复用成功块时使用「重试未完成块」按钮。退出登录会清除请求状态。`GET /v1/jobs` 与 `GET /v1/jobs/{id}` 的 `progress` 包含 `total_chunks`、`current_chunk`、`phase`，全片先验阶段块编号为 0，实际处理块编号从 1 开始；`stage` 保持原有探测、检测、分割、修复、编码、发布阶段。

成功后点「播放对比与下载」。原片采用冻结后的 MP4，成品通过 hls.js 1.6.13 播放同源 HLS，分片请求携带身份凭证。可下载合成 MP4，或 ZIP 包（解压后的 `index.m3u8` 与全部 ts）。播放器的分片、成品和打包下载均检查任务所属租户及有效期，不在播放列表写入预签名链接。依赖代码及许可证保存在 `internal/control/web/`。

- 播放：`GET /v1/jobs/{id}/hls/index.m3u8`。
- 分片：`GET /v1/jobs/{id}/hls/000000.ts` 等。
- MP4：`GET /v1/jobs/{id}/media/result`。
- 打包：`GET /v1/jobs/{id}/media/bundle`。
- 取消：`POST /v1/jobs/{id}/cancel`。
- 重试未完成块：`POST /v1/jobs/{id}/retry`，仅支持失败或待复核的 HLS 任务，累计最多三次执行。

## 分块与接缝策略

下载后先把连续 ts 无损重封装到一个统一时间轴，保留原压缩音轨。冻结的输入及描述文件写到任务的 `checkpoints/` 前缀；重试复用该快照，不重新读取可能变化的上游素材。描述文件不保存原始分片地址。

主体优先在原分片边界对齐，以 24 秒为目标选择最接近的连续范围，分片对齐时主体最多 26 秒；过长分片才在帧网格上拆开。每块前后各带 2 秒上下文（片头、片尾截断），总处理长度不超过原流水线 30 秒及 900 帧限制。末尾不足一个主体块时，若并入前块后仍满足主体及含上下文的时长上限，就合并短尾；否则保留短块。所有起止位置在全片同一帧网格上计算，避免逐块取整累积丢帧。

每块执行检测、SAM 2.1、参考背景回填、ProPainter、编码与质检。全片先每秒采样，将高通图像分成五个时间段分别求中值，再求跨段共识。只有在至少四段中方向一致的纹理才进入候选；变化的字幕因此不会成为固定水印。共识图增强后由专用 YOLOv8n 在 640、1280、1920 三种尺度验证，最低候选阈值为 0.05。模型验证和时域连通部件共同确定完整标识，不使用影片名称、品牌文本或预设位置。

一个画面允许多条独立轨迹。相邻播放图标与品牌文字通过共识连通部件补全；不同位置即使包围框相交，也不会被当成同一个对象。对自动提取的完整标识建立正常、镜像及三种尺度的模板，在全片抽样中多次出现的独立副本才初始化移动模板。每块逐帧匹配并分别关联身份，短缺口仅在同一轨迹前后可靠观测间插值，最长两秒。固定先验和模板身份在所有块中共享，避免每块重新选主框。

SAM 为每条轨迹使用独立对象编号，分别传播分割，再合并所有对象。时域支持补齐低对比笔画和图标内部，并限制 SAM 的背景泄漏。最终联合掩膜仍不得超过画面 20%；掩膜外不修复。联合面积超过 5% 时自动使用 36 帧、8 帧重叠的模型窗口和较小邻域，保持分辨率，避免多目标注意力造成显存不足。镜头切换两侧不共享模型上下文。

残留复检检查完整标识和分区部件，不能因为文字消失而忽略剩余图标。移动轨迹逐帧检查完整模板及高置信部件；固定轨迹检查输出时域共识与原始标识的相关性、投影幅度。完整标识和自适应分区分别计分，避免小图标被平均值稀释。复修只扩展有残留证据的轨迹支持，在原始画面上保留全部目标掩膜，重新执行相关镜头的参考回填和 ProPainter，最多两轮。残留非零仍阻止发布，不能以忽略多候选代替覆盖。

块前后各保留约两秒上下文。在重叠区，同一时间戳的前后块修复结果渐变融合，防止直接硬切。模型窗口的同帧重叠差异仍保留原有 35 灰度级门槛。最终编码后再次复检；接缝保存全画面和每条轨迹的原片／成品相邻帧差异及修复差异。原片与成品先统一帧率再按时间戳取图，不能把 60 帧原片和 30 帧成品的相同帧号直接比较。

多轨迹策略使用独立检查点版本，不复用旧单轨迹修复结果。冻结源仍可在相同输入任务的失败重试中复用。全片先验和轨迹随成品导出，便于离线复检。

## 时间轴与音频

在原分片累计边界强制插入关键帧，随后复制编码流按明确的 `segment_times` 切回 ts。显式禁用自动负 DTS 平移，恢复首片原视频 PTS，各片保持连续 PTS；TS 连续计数器重置用传输流自身的初始不连续标志表达，不插入媒体时间轴中断。

新播放列表保留原 `EXTINF`、`TARGETDURATION`、媒体序号等元信息，只改分片 URI。审计通过逐帧解码摘要确认 MP4 与 HLS 画面完全一致，排除 TS 切分引入的像素变化。逐片验证起点关键帧、起点 PTS 与相邻片连续性（容差一帧），验证全片帧数、时长及可解码性；最终编码画面还需逐帧通过零残留复检。分片边界只能落在视频帧网格，存在最多一帧的量化误差。

为保留逐包 PTS，TS 设置 `pes_payload_size=0`，避免合并 AAC 帧后重新推算时间戳。音轨始终 `-c:a copy`，不进入原有会重编码音频的规范化步骤。发布前比较源快照、合成 MP4、新 HLS 的 ADTS 压缩音频内容摘要，禁止转码或丢包的结果发布。同时比较冻结快照到输出的逐包 PTS（容差 1 毫秒，覆盖 TS 时间基舍入），记录音画起止偏差并要求不超过 80 毫秒。原 HLS 与 MP4 对合并 AAC 包的时间戳表达可相差一个 AAC 帧，压缩内容仍逐字节一致；验收另记录原 HLS 到冻结快照的最大差异。各块独立处理的视频没有音轨，避免音频在块边界重复或丢失。

结果写入 `{tenant}/jobs/{job}/attempts/{attempt}-{lease}/`，与原输入前缀不同。播放列表最后上传，数据库仅在所有成品上传并核验后登记成功，原输入不改动。沿用现有成品七天有效期；检查点清理应由运维按任务终态及保留策略执行。

## 验证与指标

`metrics-hls.json` 包含总处理时间、每块耗时、阶段耗时、检查点复用情况、分片 PTS、音频复制校验和接缝指标。每个主体边界输出一张 `seam-NN.jpg` 与水印区域放大图 `seam-NN-crop.jpg`：上排原片前后帧，下排成品前后帧。

指标按像素 0–255 计算：原片相邻帧平均绝对差 `source_mae`、成品差 `result_mae`，以及修复变化量的相邻帧差 `repair_delta_mae`。`roi_` 指标在自动检测轨迹周围 12 像素区域计算。独立审计还在接缝前后约半秒内计算基于水印外特征估计相机运动的补偿帧差，并以普通帧对的局部 95 分位作参照；不可靠的对齐及切镜不强行打分。这些是接缝代理指标，需要结合图片及播放判断，不能证明任意视频绝无可见闪烁。HLS 发布要求各块及合并后的水印检测残留计数均为 0；检测器的零残留也不等于人工真值。

本地验证命令：

```bash
.venv/bin/python -m pytest -q
go test ./...
python3 scripts/hls_browser_check.py
```

最终成品可用 `PYTHONPATH=. .venv/bin/python scripts/hls_verify.py --help` 查看离线审计参数，在 GPU 运行环境添加 `--detect` 可复检编码成品。

浏览器验收脚本从现有令牌文件读取身份凭证，不输出令牌和网络签名地址；结果写到 `/workspace/user-videos/hls/`。真实视频验收记录见本文末尾。

## 当前限制

多轨迹先验至少需要 15 个全片时间采样。无法形成跨时段共识、没有模型印证或无法可靠跟踪的素材仍需复核；持续不变的字幕与标识存在语义歧义时，不能仅靠置信度宣称无误。模型和模板的零残留必须结合对比图检查，不能等同于无限精度的人工真值。

仅支持完整点播 HLS、连续时间轴、H.264、8位标准动态范围、4:2:0采样、最高每秒240帧的恒定帧率，最多一条内嵌 AAC 音轨。处理与输出按现有规范最高每秒30帧，不保留源片更高的帧率。总时长不超过一小时、最多 2000 分片、单片最多 200 MiB、总下载最多 2 GiB。AES-128 及其他加密会明确返回 `HLS_UNSUPPORTED`，需先在可信环境解密再提交，密钥不能上传或复制到处理服务；不支持直播、fMP4、字节范围分片、缺失分片、时间轴中断和主列表独立音频轨。暂不跟随 HTTP 重定向，需提供最终公开地址。地址解析拒绝内网、本机及非 HTTP 协议。

完整视频的合成帧与无损块检查点需要较大磁盘和存储空间；模型推理仍是主要耗时。自动检测不可靠、残留非零、音频内容变化、PTS 或帧数校验失败均阻止发布，需检查素材或配置后重试。最多三次执行包含租约过期和人工重试。

## 部署顺序

先应用数据库迁移再重启 worker。当前部署的 API 开启 `AUTO_MIGRATE=true` 时，重启 API 会应用 `004_hls.sql`；该迁移增加进度字段，并仅为仍有尝试次数的失败 HLS 任务开放重新入队转换。成功和已取消任务继续保持终态不可改写。历史 `002_consistency.sql` 的媒体类型约束也已兼容 HLS，重复启动迁移不会退回旧约束。

API 与 worker 使用同一版本源码，保留现有模型锁、S3/R2 配置及租户身份配置。部署完成执行 `supervisorctl restart dewatermark-worker`。修改检测、修复算法或模型时应同步升级流水线或 HLS 策略版本，避免复用旧算法的检查点。定期按任务终态清理 `checkpoints/` 下成功块和草稿，保留需要的审计证据。

可在已加载运行配置的 GPU 环境中导出完整审计：

```bash
PYTHONPATH=. .venv/bin/python scripts/hls_export.py --job 任务ID --output /workspace/dewatermark-data/hls-acceptance --detect
```

导出内容含实际 R2 成品、各块自动检测轨迹、安全耗时记录、编码后逐帧质检、精确帧号的接缝图、每秒裁图、每 5 秒全帧对比图和运动补偿指标；不写入访问令牌或预签名链接。
