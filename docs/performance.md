# 视频去水印系统性能验收

## 范围与口径

基于主分支 `4fe99ba`，性能分支 `perf/speedup-pipeline`。仅做通用流水线优化，检测器、权重、置信度、分割提示、参考数量、仿射验证阈值、模型窗口及编码参数均保持画质第三版配置。没有视频名称、镜头或坐标特判，也没有手工提示。

总耗时必须包含结果发布；排队单列，避免把排队变化当作计算优化。画质第三版已有记录：8 秒片段执行 369.508 秒，其中发布 73.620 秒；25 秒片段执行 1107.898 秒，其中发布 245.384 秒。原有端到端记录分别为 373.57 秒和 1478.74 秒，后者包含 368.348 秒排队，不能直接用它宣称提速。

本轮在同一 RTX 4090 上重新执行两段基线，父进程用函数级剖析记录参考追踪、对齐、数组处理和中位数回填；子进程整体计入检测、分割与 ProPainter；发布拆分成品、元数据、逐帧掩膜。函数累计时间存在嵌套，不能相加作为总耗时。基线使用独立执行入口，最终验收通过操作台相同的上传、建任务、轮询及结果下载接口。

## 实现与取舍

参考回填预计算每张参考掩膜的外扩结果；颜色校验仅对原有验证环带的像素计算三通道差分；中位数候选只保留水印形状掩膜内的像素。仍对完整帧执行相同的仿射变换，避免裁剪改变插值舍入；双向光流、随机采样一致性验证、共识门槛和受限小孔回填均保持原算法。羽化与最后一次参考混合只计算有权重的像素，掩膜外直接复制。记录追踪、对齐、中位数、模型子进程、合成读写耗时。

中间产物发布使用最多 8 个并发上传，最多保留 16 个待完成任务。仍逐个保留原对象键和元数据，等待全部完成后才能登记任务成功；异常、取消和租约丢失会停止继续提交，取消排队项并等待正在上传的线程结束。成品仍校验长度和摘要；本地摘要只计算一次。发布记录成品与中间产物耗时。

不减少质检帧数、不调整残留阈值、不降低分辨率或帧率，也不更换编码器来换取无法保证的画质等效。模型裁剪和改变推理精度都会改变结果，本轮先验证保留推理的通用开销优化。

### 其他试验与取舍

52 帧真实素材参考回填对照：两段分别取 8/44 帧，原算法与稀疏计算算法不同通道值数均为 0。相同样本在原有 13 线程下，原算法耗时 2.948/13.317 秒，优化算法 1.657/7.731 秒；限制为单线程反而耗时 4.489/19.765 秒，已放弃。该试验存在单独预览任务的并行干扰，只用于方案筛选，不作为最终提速结论。完整任务仍用原有线程设置。

单个 60 帧窗口测得模型脚本执行 23.314 秒，其中两份预览视频编码 1.396 秒。新增仅帧输出选项跳过这两份不用的预览，保留相同帧输出；未改上游锁定仓库或权重。其收益较小，不能将整个模型耗时归因为重复编码。

模型推理与合成采用一个后台合成线程：下一窗口推理期间处理上一窗口参考回填，最多保留一个待完成合成窗口；合成和重叠混合严格按原顺序进行，镜头结束等待合成完成。峰值模型显存仍只包含一个推理子进程。模型、参考回填及读写的累计工作时间可以重叠，不能相加作为修复阶段墙钟时间。没有把重叠窗口重新回填直接删掉，因为其输入修复图像会受上一窗口混合影响。

### 部署、测试与真实操作台验收

已将生产代码同步到 GPU 部署目录并执行工作进程重启。两个计时任务通过操作台相同接口完成上传、建任务、处理、发布和下载。随后在最终部署版本上使用真实浏览器再次上传 8 秒片段，任务 `job_69a335cd877ccdf793f55750dcd561d5` 一次成功，执行 217.715 秒，发布 9.398 秒，其中成品上传与核验 0.467 秒、中间产物 8.929 秒；相对第三版执行耗时降低 41.08%。这个追加结果只作为复验，不替换上表首次 224.305 秒的记录，避免选择更好的网络样本。追加下载成品也与第三版摘要一致。

浏览器完成登录、未选文件拦截、拖拽选择、上传提交、五阶段展示、成功状态、双视频实际播放、下载、桌面/手机截图、会话恢复及退出清除。记录及截图位于 `/workspace/user-videos/speedup/操作台验收/`。

本机与 GPU 的 Python 测试均为 **48 项通过、10 项外部服务测试按默认配置跳过**；Go 测试通过。新增测试验证并发上传的上限、对象完整性和回调、存储故障及租约丢失传播、稀疏羽化与密集运算逐值相等，以及下一窗口模型推理与有序合成确实重叠。两段实际任务与真实浏览器流程提供额外的集成验收。
