# 通用模型超时与失败回退修复

本次仅验证新测试片第1块0—24秒；不运行其余块，不拼整集，不实际回跑黄果。内部视频与图像仅保留在共享电脑和Vast，不进入仓库。结果文件名不代表验收通过。

## 根因

五块均在SAM阶段触发 `worker.process.run` 的固定900秒默认值，ProPainter未执行。原始模板检测将未获逐帧YOLO印证的高通候选扩成411—460条轨迹、430—494次SAM初始化，调度组重复解码约2.9万—4万帧。不能把这些候选数量解释为真实水印数量。

旧MP4调度捕获异常后继续选帧，缺少补画结果时整块使用原帧。因此虽然有成片，实际上没有完成补画。磁盘、显存、检查点归档及SSH重连不是已确认的直接致停条件；旧GPU采样存在空缺，不能声称完整排除了所有性能影响。

## 修复

- `worker.stage_budget` 按SAM实际初始化次数、组帧、对象帧、提示和像素量估计执行预算，限制在900—7200秒，并记录工作量与实际采用上限。旧调用默认900秒保持不变。
- 独立单段入口的 `worker.model_tracks` 只用逐帧YOLO可靠观测建立对象，文字需本输入模型与品牌共识模板共同印证；不再以全画面模板峰新增轨迹。源视频、帧、先验、模板及逐帧掩膜均绑定内容摘要。字幕不直接当作水印。
- `scripts.hls_mp4_v0` 在切块、先验、模型、完整性、编码或核验失败时记录失败块、阶段及错误码并抛错。完整帧检查禁止用原帧补齐。
- `scripts.hls_single_check` 只运行一个主体及上下文，任何阶段失败都写失败报告，不生成伪完整成片。可复用逐帧校验过的SAM图层；重叠上下文必须显式启用，真实模型窗口差异仍受35上限约束。每层20%保护、36帧窗口、8帧重叠和原分辨率保持。

## 对旧v7的影响

黄果渲染、SAM调度、纹理恢复、原生合成等冻结模块未改。新增模型轨迹schema及单段入口不会被旧v7默认调用；显式预算为空时 `vision.masks` 参数与旧版相同，重叠上下文默认关闭。`process.run` 成功路径不增加像素运算或随机性。单元测试验证这些调用边界。

这是代码路径和合成测试的行为分析，不是重新实测黄果质量。遵照用户最新指示，不启动黄果模型任务，不宣称其残留、闪烁和清晰度已在本轮实测通过。
