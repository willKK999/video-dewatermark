# v15 第1块只读诊断报告

**最强证据指向“单层模型输入的水印时域不连续及其他层水印未遮”，而不是总掩膜整帧漏检。蓝块主要位于已有掩膜内部，且编码前就已存在。** 本轮未修改任何检测、分割、分层、补画或编码算法，未运行GPU推理、未出新成片。以下按证据强弱区分“已证实的输入缺口”和“尚未完全证实的模型传播因果”。

帧号从0开始。除写为`[开始,结束)`的任务窗口外，所有“X—Y帧”区间均包含两端。输入为v13e的780帧、3层实际v13b掩膜及80个任务记录，源片和成片摘要与历史绑定一致。

## 一、已证实：同一圆标跨层迁移，造成模型输入里的整段未遮

所有780帧的掩膜摘要与v13e实际输入绑定一致；各层摘要正确，图层并集和全部对象桶并集均严格等于实际联合掩膜。**联合掩膜有覆盖，不代表每次ProPainter调用使用的单层掩膜有覆盖。**

源图蓝色圆标部件轨迹0在0—172帧持续可见，蓝色部件面积9,102—9,324像素，联合掩膜覆盖率最低97.9301%，未出现源部件仍可见但掩膜为0或低于50%的帧。其真实覆盖归属却为：

任务1输入中，前83帧圆标未遮，随后120—152帧（33帧）才在当前层被遮。程序使用当前层掩膜生成模型输入，先前层不能提前处理未来层，因此前83帧圆标的这些像素确实以原始蓝色进入模型。动画部件也在`group-8 → base-0 → group-8`等迁移中形成9帧/6帧单层缺口，尽管联合掩膜仍覆盖它们。后段圆标414—599帧在第2层、600—666帧转到第1层，出现同类问题，不是仅本片早段的偶然帧号问题。

这是**可复核的模型输入污染通路**，与残留时段及同屏位置吻合，强于“总掩膜某帧完全没检到”的解释。ProPainter有双向图像/特征传播，会读取这些已知区；但没有保留成功任务的原始模型输出与内部传播来源图，因此**不能断言某个成片像素一定由上述某一帧复制而来**，也不能给出已证明的传播占比。

## 二、已证实：没有单层整帧断档的开头，也暴露了其他层蓝字

开头0—25帧圆标所属第2层的任务20，输入窗口为`[0,26)`、ROI为`[0,0,720,616]`。该窗口内第1层掩膜面积均为0，因此进入第2层模型的图像就是原帧；圆标已经遮住，但右侧第3层“蓝果”品牌蓝字尚未遮住，**每帧有5,840—5,878个源蓝色候选像素**直接暴露在同一ROI中。

该段圆标没有“同一层整帧漏遮”这一解释条件，却仍在0帧成片中留下约一万像素蓝色。后续第3层与此第2层在0—25帧的掩膜交集均为0，所以第3层不可能直接把这个圆标区域重新写回；它只是没有再处理已经形成的蓝色结果。**不同层的蓝字/图标被模型当可信上下文，是开头残影的优先怀疑原因；边缘未遮及模型自身生成也仍可能参与。**

更正v14诊断口径：此前“7个外圈候选”对应`group-0`品牌文字，**不对应圆标**。0帧圆标实际位于`base-2`，其掩膜内源蓝色有9,131像素；`group-0`掩膜内源蓝色为5,871像素。v14只扩有效联动组，没有将基础对象纳入相同统计，不能用那7个候选来否定圆标外缘漏盖，亦不能把它当圆标全区域召回率。现有联合掩膜外仍有少量蓝色，具体数量见下表，不能声称外圈绝对完整。

## 五、其他原因排查

### ROI裁剪或隐藏缩放

80个任务的施工域与记录逐一重建一致；所有输入帧内，**本任务已分配的施工像素位于ROI外为0**，距离ROI内部裁块边界3像素范围的施工像素也为0（画幅真实边缘不算内部裁边）。全部裁块宽高都是8的倍数，ProPainter的向下取8倍数预处理没有进一步裁短这些ROI。因此没有证据表明“实际掩膜被ROI裁掉一截”是主要来源。此检查不保证掩膜外的真实水印都已被检出，也不能保证上下文足够。

### 时间窗口及拼接

动画任务2/3输入`[37,153)`，覆盖3.4、3.97、4.5秒，99—107帧的单层缺口在窗口内部；3.97秒距该窗口末端还有34帧。后续任务覆盖`[145,173)`，有8帧前后重叠。蓝色残留不只出现在拼接点，0帧还没有前一窗口可拼。故“单纯窗口接缝”不足以解释大块残留，但窗口参考帧**未遮同一水印**是已经证实的输入问题；两者不能混称。

### 多层顺序及参考回填

原流程每层只读已完成的上一层，不把同层ROI输出反馈给同层模型；后来层只在自己的掩膜与施工域内写回。0—25帧前层为空、后层与圆标施工域交集0，排除了后来一层直接把该处原蓝圆标覆盖回去。实际风险是**尚未施工层的原水印，或已施工层的蓝色残影，被当作当前层已知背景**。

`CleanReferences`供体可信区使用最终联合掩膜再膨胀3像素，较ProPainter的“只遮当前层”更完整；但成功任务的原始ProPainter预测、参考回填中间结果和供体来源没有保留。只读核查全部尝试目录后，模型输出PNG保留数为0，成功任务输入帧/掩膜目录也已按既有清理逻辑移除。**本轮不能完全拆分ProPainter生成、CleanReferences回填和内侧羽化各贡献多少像素。** 未重新补画、未CPU重放生成一个替代成片来冒充历史中间结果。

## 六、仅建议，不实施

1. **使同一水印部件在完整镜头/模型输入窗口内具有稳定身份和稳定层归属。** 原基础桶不是对象轨迹，不应直接决定时域归属；装箱应同时约束同一部件跨帧连续性。对输入上下文做“源水印仍可见、当前模型掩膜未遮”的自动检查，不能只查最终并集和写回覆盖率。
2. **分开模型的可信上下文排除掩膜与最终施工域。** 所有确认水印（包括未加入OCR联动组的独立SAM对象）都不能以未来层原图或前层残影形式成为可信参考。能在20%以内联合遮住的同帧候选，优先同次建模；超预算则重新规划空间/时间任务或停止，不放宽面积、显存和接缝约束。
3. **按同帧真实并集峰值而非各对象独立峰值的简单求和评估装箱。** 本块联合掩膜实际最大只有14.7784%，虽然保守分箱生成了三层；这说明有重新规划空间，不等于已证明合为一层就能视觉通过。任何方案仍须逐帧校验20%、ROI预算和接缝MAE≤35。
4. 下次仅在批准后做可归因的小范围对照：冻结模型、参数与原掩膜像素，比较当前层输入与全水印可信区排除输入；逐阶段保留原始预测、参考回填、羽化、编码前后以及参考帧/掩膜绑定。这样才能区分模型传播、供体回填、边缘色泄漏，避免继续盲目外扩。

没有在建议中按本片帧号、固定坐标或桶ID设置修复分支；上文编号仅为证据定位。**本轮没有实现这些建议。**
