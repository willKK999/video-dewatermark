## 实现与预期

下表均为工程预期区间，**没有显卡实测支撑**。多区域数量、运动包络、模型启动、解码磁盘和光流成本都可能让结果超出区间，不能将各行倍数相乘。

| 项目 | 实现 | 阶段预期收益 | 显存预期 |
| --- | --- | --- | --- |
| 局部补画 | 窗口全部帧掩膜取并集，连通区域外扩九十六像素，传递合并相交区域；不缩放裁剪像素；不足八的倍数只填边 | 区域总面积在整帧的百分之十五至三十时，补画约二至五倍；区域多时启动成本会抵消收益 | 活动张量显著减少；总显存含固定权重成本，不能按面积直接换算 |
| 原生合成 | 张量高斯滤波、羽化和分组批量正规方程；保留固定字形系数、导数基底、六十四像素窗口及三十二像素步长 | 投影算子预期四至十倍；含光流的整个原生合成约一点五至四倍 | 每批最多四十八个局部通道窗口，禁止整帧展开巨型矩阵 |
| 七版细节融合 | 与原生合成共用后端；依次完成原有两次融合，中间画面直接留在内存，第二次仍为标准差三 | 细节阶段预期四至十倍，省去中间成品的编解码 | 与原生合成串行共用设备，不额外启动模型 |
| 分割准备和提示 | 每镜头只生成一次准备图像，生命周期之间用只读硬链接；提示保留各目标首尾、最大间隔及显著位移/面积变化；首次提示在零帧时省去重复反向传播 | 整个分割阶段约一点零至一点四倍，依赖目标数量 | 默认仍把状态卸载到处理器；不预设显存下降比例 |
| 去重复与恢复 | 内容散列校验阶段和窗口检查点；下游绑定上游输出；只改编码器不重跑模型 | 首跑省编解码；重跑只计算失效部分，不计作冷启动倍数 | 不增加推理并发 |
| 有界流水线 | 单个准备线程、单个合成线程、单卡串行模型；解码与最终编码通过有界预取和管道重叠 | 降低等待，收益以墙钟测量，不能重复计入各算子收益 | 最多一个补画进程，绝不自动多开模型 |
| 显卡编码 | 提供 `h264_nvenc` 高质量预设与低量化编码参数；音频在封装阶段直接复制 | 编码阶段有望二至五倍；须独立量测 | 只有合成完成阶段使用；本次未探测设备 |

按这些区间，三倍端到端提速有实现可能，当前不能保证达到。尤其局部补画仍逐区域启动上游脚本，原生光流仍在处理器执行。若实测超过一千秒，先用报告定位实际成本，不减少补画窗口上下文、不关闭细节融合、不降低残留门槛。

### 局部区域的通用约束

入口为 `worker.roi.plan_rois` 和 `worker.roi_inpaint.inpaint_roi`。规划使用窗口的每一张掩膜，包含多标识与移动轨迹。每个镜头单独规划，保留三十六帧窗口、八帧重叠。区域面积达到整帧百分之八十时直接退回整帧；空掩膜窗口不调用模型。贴边区域保持原像素并反射填边到八的倍数，不让上游隐式缩放裁剪图像。

模型返回后先核对尺寸和数量，再只贴回原始掩膜支持。原生干净参考回填、羽化和重叠比较均继续执行。重叠平均误差超过三十五仍要求复核，没有放宽接缝门槛。单帧镜头只复制本帧提供模型上下文，绝不引用下一镜头。

窗口检查点保存输入帧、掩膜、模型配置和执行代码的散列，完成标记原子写入；复用前逐文件验证输出。修改掩膜或代码会失效。失败时保留已经完成的窗口，合成按顺序重建，避免重复羽化旧输出。

### 张量合成的数值约定

入口为 `worker.torch_composite.TorchCompositor`。图像运算为单精度，正规方程和求解为双精度；没有启用半精度、自动混合精度或降低滤波半径。反射边界、逐通道局部联合投影、汉宁权重、正则化、跨帧固定系数、明确笔画排除和掩膜内羽化都与七版一致。局部字形和支持按批传输，避免每个通道各传一个小数组。

`hls_native_chunk --fused-detail` 先执行原生合成，再在内存内执行原有细节重合成，最后只编码一次。保留原生参考优先回填和原片六十帧的全部帧索引。去掉有损中间视频会让输出与七版存在合理编码差异，所以算子对齐测试通过后仍必须比较真实成品。

`NativeReferences` 缓存原生低频、缩小颜色、缩小支持和双向光流，复用同镜头的重复帧对；双向一致性、颜色、遮挡验证与插值方法保持原有实现。高分辨率低频滤波可使用同一张量后端。光流估计及重映射暂保留原实现。

### 分割的实际边界

七版已经是稀疏提示加逐帧传播，不能将它描述成每帧重新分割。新路径继续按镜头和生命周期分别初始化，不跨首次出现时间传播，不使用线性掩膜插值。每条轨迹保留首尾和最多三十帧间隔的提示；位移超过上次提示框对角线的百分之二十、面积明显改变时增加提示。

`SAM_PREPARE_MAX_EDGE=1024` 限制准备图像长边，并一致缩放框与掩膜提示；输出分数先恢复原尺寸再二值化，随后仍执行原有先验覆盖、面积和漂移检查。**这没有改变模型内部图像尺寸**，不能声称模型计算量按输入面积下降。进一步降低内部尺寸涉及模型构建、位置编码和稀疏笔画质量，未验证，推迟。

`SAM_HINT_STRIDE` 可供以后对照，首次基准保持三十。`SAM_STATE_ON_GPU=true` 是可选实验开关，默认关闭；没有在本次任务中启用。准备缩小与传播策略仍需与原生尺寸的七版掩膜及残留结果对照，出现漏笔画就恢复准备尺寸。

## 命令和开关

基准主环境需要原有处理依赖以及可选张量依赖：`worker/requirements-speedup.txt`。请在**独立目录的独立虚拟环境**安装，不升级正在处理整集的环境。纯处理器测试使用 `torch==2.8.0+cpu`；实际设备上的张量构建与驱动兼容性待确认。

```sh
.venv/bin/python -m scripts.hls_speedup_bench --help
.venv/bin/python -m scripts.hls_native_chunk --help
.venv/bin/python -m scripts.hls_recompose_detail --help
```

通用流水线可传入 `options={"speedup_v2": True, ...}`，启用无损帧直接解码、分割提速和局部补画。也可分别设置 `PROPAINTER_ROI=true`、`PROPAINTER_ROI_MARGIN=96`、`SAM_SPEEDUP=true`。默认旧路径不变。整集检查点包含相关配置指纹，不会混用旧整帧补画缓存。

原生及细节脚本均增加 `--backend numpy|torch-cpu|torch-cuda` 与 `--encoder libx264|h264_nvenc`。首次质量对齐仍建议 `libx264`、最终量化参数十；显卡编码的量化十与软件编码的质量参数十不是数学等价，尚不能自动切换默认。通过成品对照后再优先使用显卡编码。

现有 `worker.hls.execute_hls` 的模型阶段可使用通用提速开关；其旧的交付链路没有自动调用本次原生与连续细节渲染。**本次推荐的六十帧验证入口是下方基准脚本**。在真实基准通过前不替换整集默认交付，不将原模型分辨率的输出冒称原生六十帧成品。整集原生渲染接入、分片拼接及最终播放验收仍需单独完成与验证。

## 设备空闲后的第一块基准

以下命令仅供整集会话结束、确认设备空闲后执行。本次没有同步代码、没有运行这些命令。届时把已审阅代码放到独立工作目录，禁止覆盖 `/workspace/video-dewatermark`，也不要重启当前 worker。

先查看既有任务与设备状态，确认没有补画任务，再加载配置且不打印变量。原片继续使用已上传明文，绝不重新解密。先验、透明度、模板、图形支持和投影标定必须来自同一套自动生成的七版输入，记录其散列；不能手动修改水印框或模板来改善分数。

```sh
set -a
. /opt/dewatermark/config/runtime.env
set +a
cd /workspace/video-dewatermark-speedup-v2
export PYTHONPATH=.
.venv/bin/python -m scripts.hls_speedup_bench --run \
  --source /workspace/dewatermark-data/hls-huangguo/source.mp4 \
  --prior /自动输入目录/multitrack-prior.npz \
  --alpha /自动输入目录/calibration.npz \
  --template /自动输入目录/native-template.npz \
  --graphic /自动输入目录/graphic \
  --projection-calibration /自动输入目录/projection.json \
  --output /workspace/dewatermark-data/hls-huangguo/speedup-v2-cold \
  --duration 25 --context 2 --backend torch-cuda \
  --encoder libx264 --make-comparisons --times 5 12 20
```

输入路径中的中文目录为占位符，必须替换成对应的自动产物。脚本默认对照已接受的七版路径，可用 `--baseline` 覆盖。输出目录必须是本次独立目录，禁止指向七版产物、源素材目录或远端正在使用的运行目录。

第一次用全新输出目录计冷启动。再次使用同一目录只用于检查点续跑，并在报告中明确标记复用，不可用于冷启动提速结论。只改变 `--encoder h264_nvenc` 会重跑最终合成编码，复用模型阶段，用于比较编码画质与耗时；不应因此重跑检测、分割和补画。需要公平冷启动对照时再换全新输出目录。

已有候选可直接使用 `--candidate /候选/chunk1.mp4`，加上 `--native-report`、`--detected` 和自动支持参数复检。这个模式不运行修复模型；如果提供检测映射，残留复检仍会调用检测模型，**同样只在设备空闲后执行**。

基准会输出：

- `report.json`：处理墙钟、阶段计时与复用情况、渲染内部分项、候选规格和时长、音频压缩数据一致性、完整解码结果、原始残留证据、清晰度与相对七版指标。
- `work/performance.json`：逐窗口区域坐标、面积比例、重叠误差、模型耗时及显存峰值；未实测前没有这些模型数值。
- `metrics/`：在七版帧率上对齐全帧和每个自动轨迹包络，计算 SSIM 与 PSNR，保存逐帧原始日志。`--crop 横坐标,纵坐标,宽,高` 只增加对比区域，不影响处理掩膜。
- `audit/detail.json`：全部六十帧相邻样本；`audit/relative-clarity.json`：与七版同相位比较的全部样本、均值、第五百分位及下降超过零点零五的样本。
- `audit/residual/`：编码后的检测复检与原始候选。候选不自动抹除或重写成零，品牌图形仍需独立复检。
- `comparisons/`：原片与候选左右并排视频；原片、七版、候选三列的左上及右下截图。

阶段计时有重叠：解码预取与合成、编码管道与推理不能简单相加。最终编码计时记录管道写入阻塞及结束等待，并非编码器内部的纯计算时间。报告另记整个处理墙钟，质量对照与截图另计在本次总耗时内。

默认截图点为五、六十、一百二十、二百秒；第一块只有二十五秒，超出部分明确记录未生成。整集验收时必须在完整源片和完整成品上生成这些点，不能把第一块截图冒称整集检查。整集还必须生成由新分片无损合并的成品、检查新播放列表播放、分片时间轴、接缝、原时长和音画同步。

## 质量复核约定

水印残留必须为零；不得出现修复引起的闪现或闪烁。镜头切换须与源片比较，字幕不能算作水印。独立检测、完整品牌及短时图形检查和人工目检均需保留证据，未经复核不得更改原始候选。报告的 `通过` 和 `目检` 只有都完成并通过才能宣布验收通过；基准脚本主动保留待核验状态。

清晰度绝对值只记录，低于零点七单独列出；不得因低于零点八自动失败或返工。相对七版仍须没有明显细节退化：建议全画面和自动轨迹区域 SSIM 至少零点九八、PSNR 至少三十八分贝；同相位清晰度保留比的平均下降不超过零点零二，第五百分位下降不超过零点零五。超出时进入对照复核，不能仅凭全画面分数覆盖局部糊化。以上是本分支提出的数值复核线，真实素材还未测量，不是已获确认的验收成绩。

六十帧额外相位也必须无残留、无冻结或闪烁。基准既比较与三十帧七版重合的相位，也记录六十帧全部相邻帧的清晰度；不简单复制三十帧成品凑六十帧。音频比较直接复制的压缩数据，不以重新编码后的听感代替。

本脚本不会上传文件或修改原存储对象；安全对象前缀保持空值。以后发布必须使用不同前缀，只记录对象键，禁止记录预签名地址。

## 推迟项与限制

- 不运行多块显卡并行，先获得局部补画的实际显存峰值；当前只有准备和后处理并行。
- 不更换分割内部尺寸、不默认增加关键提示间隔，不用线性掩膜插值替代传播。
- 光流与重映射保持原算法；未用不同的插值或浮点实现换取速度，后续根据实际剖析决定是否迁移。
- 仍通过上游 ProPainter 脚本运行模型，逐区域有模型启动开销。常驻模型需要验证权重、半精度切换、释放和失败隔离，暂未改写上游模型生命周期。
- 保留无损图像检查点以便恢复，未全面改成显存帧数组；磁盘吞吐可能成为下一瓶颈。
- 未验证显卡编码与七版的视觉等效性，故保留软件编码作为首次对照默认。
- 整集接口的原生渲染交付接入、真实显卡耗时、峰值显存、全画面品牌复检、播放器与目检，以及整集新分片交付均未完成，不能宣称系统已经三倍提速并通过验收。

上游接口核对依据：[ProPainter 官方推理脚本](https://github.com/sczhou/ProPainter/blob/main/inference_propainter.py)、[SAM 官方视频预测器](https://github.com/facebookresearch/sam2/blob/main/sam2/sam2_video_predictor.py)。依赖实际固定版本仍以运行环境模型锁为准，不因上游更新自动升级。
