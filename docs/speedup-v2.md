下表均为工程预期区间，**没有显卡实测支撑**。多区域数量、运动包络、模型启动、解码磁盘和光流成本都可能让结果超出区间，不能将各行倍数相乘。

### 局部区域的通用约束

入口为 `worker.roi.plan_rois` 和 `worker.roi_inpaint.inpaint_roi`。规划使用窗口的每一张掩膜，包含多标识与移动轨迹。每个镜头单独规划，保留三十六帧窗口、八帧重叠。区域面积达到整帧百分之八十时直接退回整帧；空掩膜窗口不调用模型。贴边区域保持原像素并反射填边到八的倍数，不让上游隐式缩放裁剪图像。

模型返回后先核对尺寸和数量，再只贴回原始掩膜支持。原生干净参考回填、羽化和重叠比较均继续执行。重叠平均误差超过三十五仍要求复核，没有放宽接缝门槛。单帧镜头只复制本帧提供模型上下文，绝不引用下一镜头。

窗口检查点保存输入帧、掩膜、模型配置和执行代码的散列，完成标记原子写入；复用前逐文件验证输出。修改掩膜或代码会失效。失败时保留已经完成的窗口，合成按顺序重建，避免重复羽化旧输出。

### 张量合成的数值约定

入口为 `worker.torch_composite.TorchCompositor`。图像运算为单精度，正规方程和求解为双精度；没有启用半精度、自动混合精度或降低滤波半径。反射边界、逐通道局部联合投影、汉宁权重、正则化、跨帧固定系数、明确笔画排除和掩膜内羽化都与七版一致。局部字形和支持按批传输，避免每个通道各传一个小数组。

`hls_native_chunk --fused-detail` 先执行原生合成，再在内存内执行原有细节重合成，最后只编码一次。保留原生参考优先回填和原片六十帧的全部帧索引。去掉有损中间视频会让输出与七版存在合理编码差异，所以算子对齐测试通过后仍必须比较真实成品。

`NativeReferences` 缓存原生低频、缩小颜色、缩小支持和双向光流，复用同镜头的重复帧对；双向一致性、颜色、遮挡验证与插值方法保持原有实现。高分辨率低频滤波可使用同一张量后端。光流估计及重映射暂保留原实现。

### 分割的实际边界

七版已经是稀疏提示加逐帧传播，不能将它描述成每帧重新分割。新路径继续按镜头和生命周期分别初始化，不跨首次出现时间传播，不使用线性掩膜插值。每条轨迹保留首尾和最多三十帧间隔的提示；位移超过上次提示框对角线的百分之二十、面积明显改变时增加提示。

`SAM_PREPARE_MAX_EDGE=1024` 限制准备图像长边，并一致缩放框与掩膜提示；输出分数先恢复原尺寸再二值化，随后仍执行原有先验覆盖、面积和漂移检查。**这没有改变模型内部图像尺寸**，不能声称模型计算量按输入面积下降。进一步降低内部尺寸涉及模型构建、位置编码和稀疏笔画质量，未验证，推迟。

`SAM_HINT_STRIDE` 可供以后对照，首次基准保持三十。`SAM_STATE_ON_GPU=true` 是可选实验开关，默认关闭；没有在本次任务中启用。准备缩小与传播策略仍需与原生尺寸的七版掩膜及残留结果对照，出现漏笔画就恢复准备尺寸。

## 命令和开关

新默认原生路径的主环境需要原有处理依赖及张量依赖：`worker/requirements-speedup.txt`。请在**独立目录的独立虚拟环境**安装，不升级正在处理整集的环境。纯处理器测试使用 `torch==2.8.0+cpu`；实际设备上的张量构建与驱动兼容性待确认。

```sh
.venv/bin/python -m scripts.hls_speedup_bench --help
.venv/bin/python -m scripts.hls_native_chunk --help
.venv/bin/python -m scripts.hls_recompose_detail --help
```

通用流水线可传入 `options={"speedup_v2": True, ...}`，启用无损帧直接解码、分割提速和局部补画。也可分别设置 `PROPAINTER_ROI=true`、`PROPAINTER_ROI_MARGIN=96`、`SAM_SPEEDUP=true`。普通短视频流水线仍显式启用；正式整集默认走新原生路径。整集检查点包含相关配置指纹，不会混用七版与提速路径缓存。

原生及细节脚本均增加 `--backend numpy|torch-cpu|torch-cuda` 与 `--encoder libx264|h264_nvenc`。首次质量对齐仍建议 `libx264`、最终量化参数十；显卡编码的量化十与软件编码的质量参数十不是数学等价，尚不能自动切换默认。通过成品对照后再优先使用显卡编码。

`worker.hls.execute_hls` 的正式模型整集默认使用新原生交付。`worker.hls_native` 负责原分片边界规划与检查点，`worker.native_chunk.process_chunk` 是整集和单块基准共用的执行器，最终由 `worker.hls.deliver_hls` 完成一次高质量编码及原有分片、音频、时间轴和接缝检查。开发用替代算法保留旧冒烟路径，不将模型三十帧输出当作正式原生成品。

## 第二阶段：整集原生交付接入

正式整集的接口选项可以省略；默认相当于 `{"hls_native_path":"speedup-v2","hls_encoder":"libx264"}`。一键回退传 `{"hls_native_path":"v7"}`，也可在后续独立运行环境设置 `HLS_NATIVE_PATH=v7`。显式接口选项优先，回退强制关闭局部补画与分割提速，使用处理器纹理融合和软件编码，不受 `PROPAINTER_ROI=true`、`SAM_SPEEDUP=true` 等提速环境开关污染。回退保留七版算法和原生六十帧交付，不退回历史模型分辨率的三十帧交付。两条路径均保留两次纹理投影、标准差三的最后细节融合、三十六帧窗口及八帧重叠，最终质量参数十。

可选 `hls_encoder: "h264_nvenc"` 或 `HLS_VIDEO_ENCODER=h264_nvenc`。软件编码仍作为首次对照默认；显卡编码须在空闲设备上另做质量对照。主运行环境需安装 `worker/requirements-speedup.txt` 的张量依赖；检测、分割和补画仍使用固定清单中的独立模型环境。没有将新依赖写入或安装到主目录、远端正在运行的环境。

原片规格须是一九二零乘一零八零、恒定六十帧，音频仅复制原有压缩流；不通过放大或复制低帧率成品凑规格。边界在六十帧原片网格按原分片规划，含上下文的单块总输入至多三十秒。模型直接从对应原片帧区间解码为三十帧图像，原生参考限定在同一区间，不跨块读取额外参考。奇数帧起点也先归零采样相位再降帧。

公共自动素材由冻结原片生成一次：原有多轨迹共识先验、原生多背景模板、透明度类别与品牌前景颜色。透明度只用于区分不透明标识与透明笔画，不进行被禁止的透明反解。分块依次完成检测、按镜头和生命周期分割、完整品牌发现及图标传播、稀疏真实笔画掩膜、补画、原生参考校准、固定字形系数、两次纹理融合。完整品牌的文字须经过自动品牌文本印证，字幕不能仅因持久或被文字模型检测就加入掩膜。没有可见半透明固定标识时记录无需固定字形校准；只要存在这种标识，原有十五样本要求保持不变。

原生块输出无损图像检查点，按同时间戳合并上下文后只编码一次。所有模型在同一调度循环串行运行，准备、合成及解码预取仍有界；不同时启动多份模型。块间原生重叠差异沿用三十五的复核门槛，异常不会先被混合掩盖。

公共素材与完成块以带散列的归档保存到任务专属的新检查点前缀。原生帧以无损编码缓存，元数据、掩膜与证据单独入包；先上传内容，最后提交完成标记。恢复先验证整个归档和所有成员，拒绝越界路径与符号链接，再恢复原生帧。临时目录改变也能复用完成块；失败只重新处理未完成块，保留同一工作目录时还可复用阶段与局部补画窗口。编码器不进入模型/原生块身份，切换编码器不需要重跑修复；模式与后端进入身份，避免错误混用。

最终编码后逐块核心帧执行原有完整轨迹残留核验、完整品牌部件核验，并用既有整集残留置信度逐帧保存全画面原始模型候选。文字候选仍要做品牌文本核对，保留字幕判别依据，不删除原始候选。原始图形候选及品牌残留会阻止发布，原有模板相关与幅度门槛不变。检查失败时也将原始证据保存到任务检查点，防止工作目录回收后证据丢失。所有六十帧相邻清晰度样本、低于零点七清单及修复时间差指标均记录，清晰度绝对值不判失败。无闪现/闪烁仍须结合源片切镜逐帧目检，不能把指标记录当成目检通过。

最终沿用原分片时间轴重新封装并完整解码播放列表，检查逐包音频时间戳与压缩内容；再从新分片无损合并 `merged-from-hls.mp4`，按原片起点归零并核验规格、帧数、时长、压缩音频和逐包时序。主下载文件 `result.mp4` 使用这份合并内容，不只将它作为附加文件。自动生成左右并排视频与五、六十、一百二十、二百秒附近的左上和右下对比图。短于指定时间点的源片明确记录未生成，不虚构截图。

`report.json` 汇集块耗时、原始残留及复核依据、全部清晰度、闪烁指标、分片接缝、原片时长和输出规格、音频内容与时间轴、播放检查和目检状态。发布阶段填入安全对象键前缀，并发布对比及核验证据。`通过`、`目检` 保持待人工复核，任务工程处理完成不等于质量验收通过。`progress.log` 在每块原生处理和编码后核验完成时追加状态，未核验的残留显示待核验，不预填零。

## 设备空闲后的第一块基准

以下命令仅供整集会话结束、确认设备空闲后执行。前两阶段未执行；第三阶段已获独立目录实测授权，实际记录见文末。届时把已审阅代码放到独立工作目录，禁止覆盖 `/workspace/video-dewatermark`，也不要重启当前 worker。

先查看既有任务与设备状态，确认没有补画任务，再加载配置且不打印变量。原片使用已上传明文，绝不重新解密。默认自动准备公共素材，无需手工指定水印框或为第一块另写算法。

```sh
set -a
. /opt/dewatermark/config/runtime.env
set +a
cd /workspace/video-dewatermark-speedup-v2
export PYTHONPATH=.
.venv/bin/python -m scripts.hls_speedup_bench --run \
  --output /workspace/dewatermark-data/hls-huangguo/speedup-v2-cold \
  --path speedup-v2 --duration 25 --context 2 \
  --backend torch-cuda --encoder libx264 \
  --make-comparisons --times 5 12 20
```

脚本默认读取冻结原片并对照已接受的七版成品，可用 `--source`、`--baseline` 覆盖。换独立输出目录并加 `--path v7` 可测同一个整集执行器的回退路径；七版回退也输出六十帧，额外与既有三十帧七版按同相位比较。可用 `--prior` 复用已自动生成的全片先验；需要严格复用七版自动素材时同时传入 `--alpha`、`--template`、`--graphic`、`--projection-calibration`，脚本校验并记录内容指纹，不接受不完整组合。

输出必须位于独立目录，禁止覆盖七版成品、源片目录或正在运行的代码目录。检测、分割、完整品牌、补画、原生对齐、投影标定、合成及细节融合、编码均来自整集共用步骤；残留、品牌、清晰度、闪烁指标及 SSIM/PSNR 的独立核验耗时另列。公共素材准备成本单列，不隐藏在零耗时缓存命中中。

第一次用全新输出目录计冷启动。再次使用同一目录只用于检查点续跑，并在报告中明确标记复用，不可用于冷启动提速结论。只改变 `--encoder h264_nvenc` 会重跑最终合成编码，复用模型阶段，用于比较编码画质与耗时；不应因此重跑检测、分割和补画。需要公平冷启动对照时再换全新输出目录。

已有候选可直接使用 `--candidate /候选/chunk1.mp4`，加上 `--native-report`、`--detected` 和自动支持参数复检。这个模式不运行修复模型；如果提供检测映射，残留复检仍会调用检测模型，**同样只在设备空闲后执行**。
