# v13水印组与动画窗口实验：笔画掩膜预检通过，补画OOM后停止

在`exp/v10-sam3-ocr`上提供独立入口`worker.v13_masks`，配置为`config/v13-watermark-groups.json`。复用v12筛选结果、原始SAM3.1对象和OCR缓存，只对新增文字框运行SAM2。水印组通过同镜头共现、归一相对位置、相对尺寸以及固定位置/同步缩放/位移相关性关联。跨组具有共现证据的成员必须两两兼容，避免混合SAM对象串联独立水印。v12已拒绝的实物轨迹不能成为成员。

OCR已确认或短轨迹成员经关系验证后可在同镜头短时传播，并检查图像模板相关性；独立字幕候选保护优先。原有像素保留，新增像素记录组来源。整个组必须在同一补画层内，单组超20%直接拒绝，不能拆组绕过面积保护。逐帧图层并集与摘要另行核验。

动画依据轨迹尺寸和中心的相对变化生成区间。仅带`animation-events.json`的独立任务采用新窗口；普通任务保留原36帧/8帧计划。外部窗口最大120帧，长区间75%重叠；内部ProPainter子窗口、邻域、参考步长及35接缝阈值保持历史值。该窗口计划只有合成单元测试，尚未在本片补画中运行。

首版780帧掩膜确认动画大字与网址改善，但矩形下限重新覆盖公告栏印刷标志。按kelin追加批准，`worker.v13_stroke_merge`只重算合并：缓存SAM文字形状内用亮度局部形态对比提取笔画，小膨胀最多3像素、实际2像素；文字关系相似度约束OCR改分类，所有新增实物候选交集及对白保护区严格扣除。配置集中在`strokes`，不重新运行模型。旧矩形版及首次中断缓存全部保留。

笔画版新增515800像素帧、移除v12像素0；三个公告栏问题帧的新增实物交集均为0。第119帧缓存SAM支持中，大字覆盖19852/19899、网址7333/7344；这是缓存支持的覆盖率，不是人工水印真值的100%覆盖。三层最大面积10.4383%、6.9232%、4.5583%。独立对白及OCR保护交集为0，但机器保护区不能替代全780帧人工真值。

核对通过后实际启动780帧补画。首个动画窗口输入37:153，共116帧、720×1280；内部36帧触发GPU_OOM，按既有通用恢复缩至18帧后再次GPU_OOM，按预算停止。两次显存峰值已分配16292MiB、保留22802MiB，均没有完成窗口；没有接缝、清晰度或闪烁成片指标，没有生成成片。不得将掩膜预检通过写成补画验收通过。

一次SSH会话中断后，保留原目录，增加了计划摘要绑定及逐帧严格并集、面积、对白保护验证后复用已完成缓存的恢复方式。SAM未重复计算。失败目录及最终未通过掩膜均保留。

此前监控脚本只等待结果文件，未核实补画是否启动，造成空等。补画入口现在写入仅含PID、程序名及启动时间的记录；`scripts.watch_frozen_render`在未启动、进程退出但无结果、失败或总期限到达时退出。监控不读取进程完整参数或环境，也不会把“完成编码”当作“验收通过”。

本次结果和证据位于用户指定`out-v13/`，最终因补画显存不足未通过；GPU空闲、实例在线。完整Python420通过、12跳过，Go通过。这里只提交代码与说明，不提交测试素材，不推送或合并main。
